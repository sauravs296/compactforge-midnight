# USAGE.md — CompactForge

Day-to-day usage once the app is running (locally or on the deployed Vercel URL). All activity here targets the **Midnight Preprod network**.

## 1. Connecting Your Wallet

1. Install the **1AM Wallet** browser extension from the official Midnight docs.
2. Open the extension, create or import a wallet, and switch to **Preprod** network.
3. Fund your address using the [Midnight Preprod faucet](https://faucet.midnight.network).
4. Open CompactForge and click **Connect Wallet** in the top navigation bar.
5. Approve the connection request — the top bar badge should read **Preprod Network**.

## 2. Dashboard Pages

| Page | What it shows |
|---|---|
| **Overview** | KPI cards (contracts, avg proving time, CI runs), circuit benchmark bar chart, recent CI run feed |
| **Contracts** | All tracked `.compact` contracts, circuit list, k/rows/proving time per circuit |
| **Deployments** | On-chain deployment records — contract address, txHash, status, timestamp |
| **Proof Benchmarks** | Per-circuit proving time with inline bar chart and full parameter table |
| **CI Runs** | GitHub Actions run history — commit, branch, duration, status |

## 3. Deploying a Contract

1. Ensure your 1AM Wallet is connected and funded on **Preprod**.
2. Navigate to **Deployments** and click **Deploy token_ledger**.
3. The 1AM Wallet popup will ask you to approve the transaction.
4. After approval, CompactForge submits the transaction to the Preprod RPC endpoint.
5. Once indexed, the Deployments table updates with the live **contract address** and **txHash**.
6. Copy these values into the `README.md` placeholders for your hackathon submission.

## 4. Triggering a CI Run

Push any change to `contracts/**` on `main`. The `contracts.yml` GitHub Actions workflow will:
1. Install the Compact compiler.
2. Compile `token_ledger.compact` and report any errors.
3. Run `scripts/compile-and-test.sh` to measure proving times.
4. Upload `benchmark.json` as a GitHub Actions artifact.
5. POST the benchmark payload to the CompactForge dashboard API.

## 5. Running Tests Locally

```bash
npm run test                      # Vitest unit test suite
bash scripts/compile-and-test.sh  # Compact contract compilation + benchmark (WSL Ubuntu)
```

## 6. Reading the Benchmark Chart

- **Bar width** = proving time relative to the slowest circuit (`mint` at ~1510 ms).
- Each circuit's **k** value is the SRS (Structured Reference String) size required — higher k = heavier proof.
- **Rows** are ZK constraint rows generated by the Compact compiler.
- A regression on `transfer` or `mint` after a circuit change is expected — track it over commits on the **Proof Benchmarks** page.

## 7. Common Questions

**Why does the dashboard show demo data?**
CompactForge needs a live Preprod deployment (contract address + txHash) to populate the Deployments table from the indexer. Follow Section 3 above to deploy and populate it.

**My wallet connects but deploy fails.**
Check that your 1AM Wallet is on **Preprod** (not Mainnet or Undeployed) and that your address has tDUST balance from the faucet.

**Where do the prover/verifier keys come from?**
Generated in WSL Ubuntu by running `compact compile` — the build output lands in `contracts/token_ledger/build/token_ledger/keys/`. These are committed for the demo; in production CI regenerates them per compile.
